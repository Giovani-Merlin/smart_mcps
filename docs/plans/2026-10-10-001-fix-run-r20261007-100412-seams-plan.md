## Decisions

- **The driver-item hold is a scheduler hold reason, recorded through a new
  `driver-item` subcommand, and surfaced as an escalation only when HITL is
  on.** A group is held while a COMPLETED/RESOLVED dependency still carries a
  required `Run (driver):` item that neither the coder's latest report nor
  `groups/<gid>/driver-items.json` marks run; `status` shows the hold; the run
  log says how to release it. With `[escalation] enabled` and a tier that
  includes the new `driver_items_pending` kind (`on_stuck`, `interactive`),
  one request is raised per held group so the driver's Monitor fires; `answer`
  (any action but `skip`/`abort`) releases without recording, and a timeout
  releases too (today's behaviour). Alternatives rejected: an escalation-only
  gate (nothing is ever recorded, so auto-finish and `status` stay blind; a
  4-hour timeout blocks a run with HITL off), and a `wait_for_driver` marker
  in the plan (one more thing a planner forgets).
- **The harness hash is pinned only after the smoke and the first scoring
  exit 0, and `retry` deletes the pin.** The pin exists to catch a harness
  edited under a running loop; a failed smoke never scored anything, so there
  is nothing to protect. `retry` is the operator's explicit "I changed the
  world" — it removes `run/eval/harness.sha256` and logs the old combined
  hash so the report can see the harness changed. Rejected: pin-on-success
  alone (a harness fixed after a *successful* first attempt still fails the
  retry), and retry-reset alone (a crash re-entry after a failed smoke keeps
  the stale pin).
- **The untracked ladder archives on the first strike and merges; it never
  relaunches on its own.** The escalation stays (`on_stuck`): `retry` with no
  text re-runs the gate, `retry` with text is the operator's explicit
  relaunch (the note names `git mv … .coder-scratch/` and never "delete").
  Every other outcome (timeout, autonomous, `answer`) moves the paths to
  `groups/<gid>/untracked/`, spreads the informational surprise, re-runs the
  gate and merges. Rejected: moving leftovers into `.coder-scratch/` and
  relaunching (one generation on every probe artifact; the only observed
  strikes were probe artifacts, and recipe groups' forgotten outputs are
  already caught by `_commit_declared_outputs` / "no commits ahead").
- **The gate and driver data steps exclude each other through one run-level
  flock, `data-step.lock`, with a `data-step` wrapper the driver uses.**
  `merge_group` holds it around `run_preflight`; `smart-mcps-orchestrate data-step <run> -- <cmd>` holds it around the command; whichever side waits
  logs why. A launch-time warning names the wrapper whenever `data_dirs` is
  configured. Rejected: warning only (the race stays on the driver's
  attention, which lapsed twice in that run).
- **`on_group_failure` defaults to `overlap`.** Every designed fail-fast
  (census bar, unreviewed fixture) under `halt` cost a `retry` + `resume`
  cycle and a new driver process; `overlap` still strands dependents and
  file-overlapping groups. `--on-failure halt` remains the escape hatch, and
  the halt report's advice text stays correct because a halted run now only
  arises from an explicit `halt`. Rejected: keep `halt` and document (the
  user chose the flip).
- **A run-group item is satisfied by a declared command whose argv starts
  with the item's `Run:` argv.** Exact equality missed g9-1/g11-1 because the
  recipe adds `--out <measurements>`. A prefix is the smallest rule that
  passes those and still rejects the `--smoke` item (its extra flag is not in
  the declared command).
- **One-pager commit pointers validate against every commit in
  `base..tip`, not just the two endpoints.** `GitRangeFacts` gains the
  8-character prefixes of `git rev-list base..tip` plus `base`.
- **Live tests are one file per seam.** Four files sharing one module would
  pull four units into one group by file affinity; each unit owns its own
  `tests/test_<seam>_live.py`, run by the driver (`-m llm`).
- **No ADR.** Every decision above is a one-line default or a mechanism a
  later plan can replace without migration.
